# Learning While Building

사용자는 자연어만으로 프로젝트를 진행할 수 있어야 합니다. 설명은 프로젝트 개발을
멈추게 하는 긴 강의가 아니라, 현재 선택과 코드를 이해할 수 있게 돕는 형태입니다.

## 설명 원칙

- 지금 바꾸는 파일과 역할을 직접 가리킵니다.
- 요구사항 때문에 선택한 기술과 단순 추천을 구분합니다.
- 확인한 사실, 사용자 결정, AI 추론, `UNKNOWN`을 구분합니다.
- 작은 프로젝트에는 필요한 만큼만, 큰 프로젝트에는 경계와 단계까지 설명합니다.
- 세션 끝에는 완성된 동작과 다음 마일스톤의 관계를 알려줍니다.

예시:

```text
이번 마일스톤은 주문 접수의 끝-to-끝 흐름을 만듭니다.
Controller가 요청을 받고, Service가 주문 규칙을 적용하며,
Repository가 주문을 저장합니다. 결제 연동은 다음 단계로 남깁니다.
```

```text
멀티 모듈은 예상 규모만으로 추가하지 않았습니다.
현재 확인된 주문과 정산의 배포·변경 주기가 분리될 때 모듈 경계를 확정합니다.
```

## 세션 종료

마지막에는 다음을 명확히 합니다.

- 이번 마일스톤에서 사용할 수 있게 된 것
- 중요한 기술·설계 결정
- 테스트 또는 실행 결과
- 확인하지 못한 항목
- 전체 로드맵에서 다음에 만들 것
