# Mode: start

외부 Spring 프로젝트를 처음 만들거나 계속 확장하는 유일한 모드입니다. 빈 repo,
README-only repo, 작은 애플리케이션, 대형 프로젝트 모두 같은 흐름을 사용합니다.

공통 안전 규칙은 `AGENTS.md`에 있습니다.

## 진행 모델

사용자가 기술 결정을 모두 알 필요는 없습니다. 요구사항과 현재 evidence를 바탕으로
추천안을 제시하고, 사용자가 잘 모르겠다고 하면 추천으로 진행합니다. 되돌리기 쉽고
검증 가능한 마일스톤으로 나누되, 프로젝트 전체 규모를 작게 제한하지 않습니다.

## UX 규칙

- 질문은 한 번에 하나만 합니다.
- 먼저 프로젝트 청사진과 추천 첫 기능을 요약하고 `추천으로 진행 / 항목별 수정 /
  직접 구성`을 선택하게 합니다. 기술은 선택한 기능에 필요한 범위부터 제안합니다.
- 개별 질문은 짧게 하고 관련 있는 대표 선택지 2~4개와 `기타 / 직접 입력`을 줍니다.
- 선택지에는 추천과 즉시 영향을 한 문장으로 포함합니다.
- 질문이 이어지면 진행도를 보여주고 `나머지는 추천`과 `이전 선택 변경`을 허용합니다.
- 이미 답이 evidence나 승인된 요구사항에 있으면 다시 묻지 않습니다.
- 한 세션에는 하나의 일관되고 검증 가능한 마일스톤을 진행합니다.
- 구현하면서 중요한 선택과 파일 역할을 짧게 설명합니다.
- 세션이 끝나기 전에 테스트 또는 실행 확인을 합니다.
- 끝에는 완료 내용, 검증 결과, 남은 UNKNOWN, 다음 선택지를 줍니다.
- JSON은 내부 기준으로 사용하고 사용자에게는 목표·사용자 가치·흐름 중심 요약을 먼저
  보여줍니다.
- AI 추천과 추론을 사용자 발언으로 표현하지 않습니다.
- 프로젝트 목표 승인, 기능 명세 승인, 파일 적용 승인은 서로 대체하지 않습니다.
- 프로젝트 개요와 첫 기능을 한 화면에서 확인했다면 한 번의 응답으로 각각 승인할 수
  있습니다. 내부 해시나 JSON 편집은 사용자에게 요구하지 않습니다.

## 규모에 따른 시작

### 작은 프로젝트

README 또는 사용자의 목표에서 첫 기능을 정하고 빠르게 실행 가능한 형태를 만듭니다.

### 대형 프로젝트

코드를 한꺼번에 만들지 않습니다. 먼저 다음을 현재 단계에 필요한 깊이로 정리합니다.

- 프로젝트 목표와 주요 사용자
- 기능 범위와 비기능 요구사항
- 단계별 로드맵
- 모듈 또는 경계 후보
- 데이터, 외부 연동, 보안, 운영 요구
- 각 단계의 검증 방법과 UNKNOWN

그 뒤 로드맵의 첫 번째 검증 가능한 마일스톤부터 구현합니다. 프로젝트가 이미 시작된
경우에는 `docs/progress.md`, README, 빌드 파일, 현재 소스를 읽고 다음 마일스톤을
선택합니다.

## 기술 선택

요구사항이 없다면 단순하고 널리 쓰이는 Spring Boot 구성을 추천합니다.

- Java 17 이상
- Spring Boot
- Gradle 또는 Maven
- 필요한 Spring starter
- JUnit

다음 기술은 금지 대상이 아닙니다. 요구사항이나 현재 단계에서 필요할 때 추가합니다.

- Spring Security와 인증·인가
- 운영 데이터베이스와 마이그레이션
- 메시징, 캐시, 배치
- Docker와 배포 설정
- 프론트엔드 프레임워크
- 멀티 모듈 또는 분산 시스템 구성

프로젝트가 클 것이라는 이유만으로 미리 추가하지는 않습니다.

첫 구현 전에는 target의 `docs/project-profile.md`에 기술 결정을 기록합니다. 모든
기술을 지금 확정하지 않고 `NOW`, `SOON`, `DEFERRED`, `NOT_USED`, `UNKNOWN`으로
구분합니다. 자유 입력은 정식 선택으로 보존하고, 선택 조합은 구현 전에 호환성·비용을
검토합니다.

## 기능 명세

기술 선택만으로 프로젝트 준비가 끝난 것으로 보지 않습니다. 자연어 목표를 프로젝트
개요와 기능 후보로 정리하고, 다음 vertical slice 하나를 승인 가능한 기능 명세로
만듭니다. REST API뿐 아니라 화면, 배치, 메시지, 스케줄, 외부 연동도 같은 흐름을
사용하며 API와 관계형 DB를 강제하지 않습니다.

구조화 JSON은 기준 원본이고 Markdown은 사용자용 파생 보기입니다. 중요한 UNKNOWN과
확인되지 않은 AI 추천 업무 규칙이 남아 있으면 설계와 구현으로 넘어가지 않습니다.

## 세션 흐름

```text
Preflight
Project evidence and progress
Scope or roadmap check
Feature choice
Relevant technology decisions
Approved feature specification and milestone
Implementation
Verification
Progress update
Next milestone choices
```

## 산출물

- `<target>/docs/progress.md` — 현재 목표, 완료 마일스톤, 결정, UNKNOWN,
  다음 마일스톤을 기록합니다.
- 세션 요약 — 채팅으로 제공합니다.
- 대형 프로젝트의 로드맵과 설계 문서는 필요할 때 target의 `docs/`에 둡니다.
