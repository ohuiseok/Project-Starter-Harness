# Spring Change Workflow

Use this reference for changes to target Spring behavior.

1. Require or create a Context Pack.
2. Check for unreviewed auto-check reports.
3. Re-check latest target code evidence for related auto-check candidates.
4. Identify the customer scope.
5. Identify common or shared areas.
6. Include baseline/current mismatch in the plan when branch behavior differs.
7. Create an impact analysis and Customer Impact Matrix when relevant.
8. Identify verification commands and test gaps.
9. Present a minimal plan.
10. Wait for explicit human approval.
11. Implement only the approved change.

Do not refactor unless the approved plan explicitly includes a separate
refactoring task.
